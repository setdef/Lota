# Lövetest's ByteData test compares a byte with a string

At the pinned LÖVE commit, `b7daef0f7`. Written as the report we would file; LÖVE accepts none made with generative AI (AGENTS.md, "Reporting upstream"), so it stays here.

`love.test.data.ByteData` (`testing/tests/data.lua`, lines 29 to 34) reads the fifth byte of `"helloworld"` through `getFFIPointer` and compares it with the string `"o"`. Indexing a `uint8_t*` cdata gives a Lua number, 111, so `test:assertEquals('o', byte5)` would fail.

It never runs: the check is guarded by `ffi ~= nil`, a global that neither Lövetest's `main.lua` nor its classes set, so LÖVE skips it, and the bug stays hidden.

## To reproduce

Set the global before the test runs, as `ffi = require("ffi")` in Lövetest's `main.lua`, and run the data tests on a LÖVE built with LuaJIT. The ByteData test then fails its comparison of `"o"` with `111`.

## A fix

Compare with the byte's number, `string.byte("o")`, or read the byte as a string with `ffi.string(ptr + 4, 1)`; and require `ffi` where the test means to use it, or test for it with `pcall(require, "ffi")`, so the check runs where LuaJIT's FFI does.

## What Lota does

Lota's translation (`test/lovetest/tests/data.rb`) leaves the guarded check out, as LÖVE skips it. Lota's pointers, Fiddle's, are checked in `test/native/data_test.rb`, where the fifth byte read as a string through `Lota::Data#pointer` is `"o"`, and `#ffi_pointer` reads `"helloworld"`.
