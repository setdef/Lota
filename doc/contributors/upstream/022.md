# `love.mouse.getGlobalPosition` leaks the display list and can misplace the pointer

At the pinned LÖVE commit, `b7daef0f7`. Written as the report we would file; LÖVE accepts none made with generative AI (AGENTS.md, "Reporting upstream"), so it stays here.

`Mouse::getGlobalPosition` (`src/modules/mouse/sdl/Mouse.cpp`, lines 166-197) finds the display the pointer is on and the pointer's place on it. It has two faults.

## The display list is never freed

It takes the displays from `SDL_GetDisplays` (line 175), whose array, SDL 3's documentation says, the caller frees with `SDL_free`. Nothing frees it, so every call leaks an array of one `SDL_DisplayID` for each display. A game that reads the global position every frame leaks a few bytes a frame for as long as it runs.

## The pointer's place subtracts every display before its own

The loop subtracts each display's origin from the pointer's desktop position before it checks whether the pointer is on that display (lines 184-185), and does not start again from the desktop position for the next one. So for the display at index `k` it reports the desktop position less the origins of displays 0 to `k` together, where it means less the origin of display `k` alone. That is right only while the displays before `k` have their origins at 0, as a primary display at the desktop's origin has. With three displays side by side at x = 0, 1920, and 3840, a pointer at x = 4000 on the third is reported at 4000 - 0 - 1920 - 3840 = -1760, where it is at 160. When the pointer is on no display, the index falls back to the first (lines 192-193), but the position keeps every display's origin subtracted.

## To reproduce

Call `love.mouse.getGlobalPosition()` with the pointer on the third of three displays placed side by side, or on any display after one whose origin is not the desktop's. For the leak, call it in `love.update` under a leak checker, such as AddressSanitizer's on Linux.

## A fix

Free the list once the loop is done (`SDL_free(displays)`), and compute the place from the found display's own origin: `x = globalx - frect.x` and `y = globaly - frect.y` for the display that contains the point, and the desktop position, or the first display's, when none does.

## What Lota does

`Lota::Mouse.global_position` calls LÖVE's `Mouse::getGlobalPosition` through the binding generator, so it answers as LÖVE answers, on one display or several, and leaks as LÖVE leaks. Lota could avoid both with a binding of its own, but the place it reported on three or more displays would then differ from LÖVE's, which the maintainer has not decided on. Lota's test (`test/native/cursor_test.rb`, `test_the_global_position_is_the_pointer_on_its_display`) runs on one display, where the two agree.
