# Readback into a wider ImageData reads nothing under Mesa

At the pinned LÖVE commit, `b7daef0f7`. Written as the report we would file; LÖVE accepts none made with generative AI (AGENTS.md, "Reporting upstream"), so it stays here.

`love.graphics.readbackTexture` into a given `ImageData` wider than the rectangle read leaves the `ImageData` unchanged when OpenGL has `glGetTextureSubImage`, as Mesa's llvmpipe does (OpenGL 4.5). LÖVE sets the row length to the `ImageData`'s width but tells OpenGL the buffer holds only `rect.w` by `rect.h` pixels (`src/modules/graphics/opengl/GraphicsReadback.cpp`, lines 65 to 74; `src/modules/graphics/opengl/Texture.cpp`, lines 488 to 503). Mesa refuses it: `GL_INVALID_OPERATION in glGetTextureSubImage(out of bounds access: bufSize (16) is too small)`, seen with `MESA_DEBUG=1`. A destination as wide as the rectangle reads correctly, and macOS never meets it, since it reads with `glReadPixels`, which takes no size.

Lota reads the rectangle into an `ImageData` of its own size and copies the rows (`Lota::Graphics.readback_texture`, ext/lota/native/texture.cpp).
