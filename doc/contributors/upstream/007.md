# `DistanceJoint:setLength` has no effect: Box2D 2.4 holds the joint at a length LÖVE never changes

At the pinned LÖVE commit, `b7daef0f7`. Written as the report we would file; LÖVE accepts none made with generative AI (AGENTS.md, "Reporting upstream"), so it stays here.

LÖVE 12 builds Box2D 2.4, whose distance joint has three lengths: a rest length for its spring, and a least and a greatest length it keeps the two anchors between. `DistanceJoint`'s constructor makes the joint with `b2DistanceJointDef::Initialize` (`src/modules/physics/box2d/DistanceJoint.cpp`, line 42), which sets all three to the anchors' distance (`src/libraries/box2d/dynamics/b2_distance_joint.cpp`, lines 44-55). `DistanceJoint::setLength` then calls `b2DistanceJoint::SetLength` alone (`DistanceJoint.cpp`, lines 51-54), which changes the rest length and nothing else (`b2_distance_joint.cpp`, lines 338-343). While the least and greatest lengths are equal, Box2D's solver ignores the rest length: it holds the anchors at the least length (lines 182 and 243-259 for the velocities, 283-285 for the positions), and it sets up the spring only when the two differ (line 123). LÖVE binds neither `SetMinLength` nor `SetMaxLength`, so they stay equal for the joint's life.

The result is that `joint:setLength(n)` changes what `joint:getLength()` returns and nothing the World does: the Bodies stay at the distance the joint was made with. `setStiffness` and `setDamping` are likewise read back and never used. A game that shortens a rope or a spring this way gets no error and no change.

To reproduce: make a World with no gravity, a static Body at 0, 0 and a dynamic one with a shape at 60, 0, join them with `love.physics.newDistanceJoint(a, b, 0, 0, 60, 0)`, call `joint:setLength(30)`, and step the World for a second. `joint:getLength()` returns 30 and `b:getX()` still returns 60.

A fix would make `setLength` set all three lengths, as `Initialize` does, when the joint is rigid, or bind `setMinLength` and `setMaxLength` (with getters) and document that the rest length acts only between them.

What Lota does: nothing different from LÖVE. Lota runs LÖVE's own `DistanceJoint`, so `Lota::Physics::DistanceJoint#length=` behaves exactly as `setLength` does in LÖVE, and `test/native/physics_joints_test.rb` (`test_a_distance_joint_keeps_its_first_length_as_in_love`) holds it to that. Changing it would take a patch to LÖVE's engine or a binding that reaches past `DistanceJoint` to Box2D, and either would make a Lota game behave differently from the same game in LÖVE, which ADR 001 puts first, so it is the maintainer's to decide.
