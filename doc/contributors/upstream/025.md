# On Vulkan, the error handler crashes after a present that throws before its submit

At the pinned LÖVE commit, `b7daef0f7`, and in love-android's `main` branch at `1c89bb0b2e` (2026-11-03), whose LÖVE 12 is a commit past `b7daef0f7` whose changes to `src/modules/graphics/vulkan/Graphics.cpp` touch none of the functions below. Written as the report we would file; LÖVE accepts none made with generative AI (AGENTS.md, "Reporting upstream"), so it stays here.

When `love.graphics.present` throws on Vulkan after it has ended the frame's command buffer and before it has submitted it, the game does not show its error: `love.errorhandler` crashes the program with SIGSEGV as it makes its font.

## What happens

`submitGpuCommands` ends the frame's command buffer (`src/modules/graphics/vulkan/Graphics.cpp`, line 478) and then submits it (line 514). Between the two it can throw: `endRecordingGraphicsCommands` throws if `vkEndCommandBuffer` fails (lines 1591-1593), `renderFinishedSemaphores.at(imageIndex)` throws when the image has no semaphore (line 499, `doc/contributors/upstream/024.md`), and a failed `vkQueueSubmit` throws (lines 515-516). The command buffer is then neither recording nor submitted, and nothing begins it again: only `beginSwapChainFrame`, at the end of a present that succeeds (line 668), and a `SUBMIT_RESTART` submit (line 580) begin it.

`love.errorhandler` is the next to draw. It makes a font first (`src/modules/love/callbacks.lua`, line 259), and the font's texture records a clear into the command buffer that `getCommandBufferForDataTransfer` returns (lines 1596-1602, and `vulkan/Texture.cpp`, line 467 on), the one that has ended. Recording into a command buffer that is not recording is undefined in Vulkan. Adreno's driver dereferences a null pointer.

That is on a OnePlus Nord N30 5G (Android 14, Adreno 619, Vulkan 1.1.128), with love-android's debug APK from its CI run 41632391450. The same crash, at the same address, ended a Lota game there after `vector`, in `Lota::Graphics::Font.new`, which Lota's error handler calls as LÖVE's does. A failed `vkQueueSubmit` leaves the same state; on that phone, a build of Lota's engine that threw in place of its 40th submit crashed the same way unless the frame was recorded again.

## A fix

When the commands end but are not submitted, record the frame again from its start before the error leaves `submitGpuCommands`, as `beginSwapChainFrame` records it once it has the image (lines 1487-1518): begin the command buffer again, which `vkBeginCommandBuffer` may do since the command pool resets its buffers (line 3536) and this one never reached the GPU; record the transitions of the swap chain image and the color and depth images from `VK_IMAGE_LAYOUT_UNDEFINED`; and keep `imageRequested`, since no submit waited for the image's semaphore. What the frame drew is lost, which is no loss on the way to an error screen, and the next present can succeed, as the error handler's does.

## What Lota does

The command buffer and the frame's state are private to LÖVE's `Graphics`, and no function of LÖVE's begins its command buffer again without first ending it, so nothing in Lota's own code can do this. Lota compiles `vulkan/Graphics.cpp` with a patch, `ext/lota/engine/vulkan_submit.patch`, wherever it builds LÖVE's Vulkan renderer. It adds a guard to `submitGpuCommands` from before `endRecordingGraphicsCommands` to after `vkQueueSubmit` succeeds, which does the above if anything throws between them, and catches what it throws itself, so the error that unwound through it is the one `present` raises.

On the Nord, with the build that threw in place of its 40th submit, a Lota game in landscape with vsync off on Vulkan showed Lota's error screen with that error, and went on running its error handler's frames, presenting each, until it was stopped. A present that fails after its submit, as when `vkQueuePresentKHR` fails with an error LÖVE does not rebuild the swap chain for (lines 651-652), leaves a submitted command buffer and no image acquired; neither the patch nor this report covers it.
