# `love.audio.getRecordingDevices` lists a nameless device when nothing can record

At the pinned LÖVE commit, `b7daef0f7`. Written as the report we would file; LÖVE accepts none made with generative AI (AGENTS.md, "Reporting upstream"), so it stays here.

When OpenAL reports no default capture device, `Audio::getRecordingDevices` tries to open one itself, to read its name (`src/modules/audio/openal/Audio.cpp`, lines 573-591). It checks whether that worked with `alGetError()`, but `alcCaptureOpenDevice` is an ALC call: it returns a null device and sets the ALC error, which `alGetError` does not report, so the check passes. LÖVE then reads the name with `alcGetString(defaultdevice, ALC_CAPTURE_DEVICE_SPECIFIER)` on the null device, which returns the list of capture devices, empty here, and closes the null device. The empty name goes into the list (line 593), and the loop that follows adds no other, so the function returns one `RecordingDevice` named `""`. Its `start` returns `false`, since there is nothing to open.

To reproduce: run LÖVE with an OpenAL Soft configuration that has no capture backend, such as Lövetest's own `testing/resources/alsoft.conf` (`drivers = wave`, whose wave writer only plays), and call `love.audio.getRecordingDevices()`. It returns a table of one device, whose `getName()` is `""` and whose `start()` returns `false`. Lövetest's `love.test.audio.RecordingDevice` test skips only when the table is empty, so on such a machine it fails at "check recording started"; LÖVE's CI skips it on its runners before it asks.

A fix would test the device: `if (defaultdevice != nullptr)`, or `alcGetError(nullptr) == ALC_NO_ERROR`, before reading its name, and return the empty list otherwise, as the comment beside the check intends.

What Lota does: nothing different from LÖVE. `Lota::Audio.recording_devices` returns what LÖVE's engine returns, the nameless device among it, as precedence 2 asks, so the maintainer decides whether to drop it. Lota's test suite plays into the wave writer on every computer (`test/alsoft.conf`), as LÖVE's CI does on its runners, so its translation of the recording test skips wherever that is so (`Lovetest::WAVE_WRITER`), as Lövetest skips on a runner.
