# On Linux with zenity, a cancelled `love.window.showFileDialog` reports one empty file

At the pinned LÖVE commit, `b7daef0f7`, with SDL 3.4.10, the SDL LÖVE's Linux build uses (`love-appimage-source`'s `SDL3_BRANCH`). Written as the report we would file; LÖVE accepts none made with generative AI (AGENTS.md, "Reporting upstream"), and SDL asks that generative AI not be used in contributing to it, so it stays here.

The fault is SDL's, and LÖVE passes it on. A game that tells a cancelled dialog by an empty list of files, as SDL's documentation of `SDL_DialogFileCallback` says it may, takes a cancel on Linux for a choice of the file `""`.

## What happens

SDL's documentation of `SDL_DialogFileCallback` (`include/SDL3/SDL_dialog.h`) says the file list is empty when the user cancelled the dialog. On Linux, SDL shows the dialog with zenity when the desktop has no file chooser portal, or when `SDL_FILE_DIALOG_DRIVER` is `zenity` (`src/dialog/unix/SDL_unixdialog.c`, lines 41-64). zenity prints nothing and exits 1 when the user cancels. `run_zenity` (`src/dialog/unix/SDL_zenitydialog.c`, lines 224-309) reads zenity's output with `SDL_ReadProcess`, which returns an empty string rather than `NULL` for no output (`SDL_LoadFile_IO`, `src/io/SDL_iostream.c`, lines 1249-1318). It always puts that string first in the list (lines 266-271), and splits it at each newline after it. For exit status 0 or 1 it passes the list on (lines 290-292), so a cancel arrives as a list of one empty name, not an empty list.

LÖVE copies the list as it is (`fileDialogCallbackSDL`, `src/modules/window/sdl/Window.cpp`, lines 1514-1543), and `fileDialogCallback` (`src/modules/window/wrap_Window.cpp`, lines 655-686) gives the game a table holding one empty string.

## To reproduce

On Linux with zenity installed and no file chooser portal, or with `SDL_FILE_DIALOG_DRIVER=zenity` in the environment:

```lua
function love.load()
  love.window.showFileDialog("openfile", function(files)
    print(#files, files[1] == "")
  end)
end
```

Cancel the dialog. LÖVE prints `1 true`, where SDL's documentation promises `0`.

## A fix

In `run_zenity`, pass an empty list when zenity printed nothing (`bytes_read == 0`). LÖVE could guard against it too, by leaving out an empty name as it copies the list, since no path is empty.

## What Lota does

Lota leaves every empty name out as it copies the list into the Array the game's block receives (`file_dialog_callback`, `ext/lota/native/window.cpp`), so a cancelled dialog chooses no files on every platform, as SDL documents. Any answer LÖVE gives that holds no empty name, Lota gives unchanged. `test/native/file_dialog_test.rb` (`test_on_linux_cancelling_zenity_chooses_no_files`) cancels the dialog through a program that answers as zenity does, and finds no files.
