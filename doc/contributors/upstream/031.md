# `love.filesystem.mount` refuses a dropped file

At the pinned LÖVE commit, `b7daef0f7`. Written as the report we would file; LÖVE accepts none made with generative AI (AGENTS.md, "Reporting upstream"), so it stays here.

A game cannot mount a file dropped on its window. `love.filesystem.mount(file, "dropped")`, with the File that `love.filedropped` receives, raises "bad argument #1 to 'mount' (string expected, got userdata)", though LÖVE lets a dropped path be mounted for just this purpose. A File from `love.filesystem.openNativeFile` is refused the same way.

## What happens

When a file is dropped, `Event.cpp` (`src/modules/event/sdl/Event.cpp`, lines 536-562) first lets its path be mounted, "so zips or dirs can be mounted" (lines 541-542). It then opens the file with `Filesystem::openNativeFile`, which makes a `NativeFile` (`src/modules/filesystem/Filesystem.cpp`, lines 71-74), and hands it to Lua in a Variant of type `File` (line 558). `w_openNativeFile` likewise pushes the `File *` it gets with `luax_pushtype` (`src/modules/filesystem/wrap_Filesystem.cpp`, line 273), which takes the type from the pointer's class, `File` (`src/common/runtime.h`, lines 345-349). So the Lua value's type is `File`, though the object is a `NativeFile`: `file:type()` is `"File"`, and `file:typeOf("NativeFile")` is `false`. Nothing in LÖVE pushes an object with `NativeFile`'s type, though `wrap_NativeFile.cpp` registers it (line 36).

`w_mount` (`wrap_Filesystem.cpp`, lines 113-153) has a branch for a NativeFile, which mounts it by its filename (lines 140-144). It asks `luax_istype(L, 1, NativeFile::type)`, which compares the value's type, not the object's (`src/common/runtime.cpp`, lines 694-705). `File` is not a kind of `NativeFile`, so the branch never runs, and the value falls through to `luax_checkstring` (line 146), which raises.

## To reproduce

We read this and did not run it. In a game whose `main.lua` is

```lua
function love.filedropped(file)
	print(pcall(love.filesystem.mount, file, "dropped"))
end
```

drop a zip on the window. By the code above it prints `false` and the "string expected" error, where it should print `true`.

## A fix

Push the files with their own type: `luax_pushtype(L, NativeFile::type, t)` in `w_openNativeFile`, and `&love::filesystem::NativeFile::type` in the Variant `Event.cpp` makes. A dropped file then answers `typeOf("NativeFile")`, and `w_mount` mounts it. Testing the object instead, with a `dynamic_cast` to `NativeFile` in `w_mount`, would fix the mount alone.

## What Lota does

Lota binds every File as one class, `Lota::Filesystem::File`, whose `object_type` is `"File"` and whose `type_of?("NativeFile")` is `false`, as LÖVE's are. `Lota::Filesystem.mount` asks the engine object itself whether it is a NativeFile (`native_file_name`, `ext/lota/native/filesystem.cpp`), and mounts one by its filename, as `w_mount`'s branch means to, so a game can mount a file dropped on its window. Any other File raises TypeError, as LÖVE raises for it. Whether Lota should raise for a NativeFile too, as LÖVE does, is a question for the maintainer.
