# libvorbis builds with `-ffast-math` on Linux, which makes x86_64 binaries need libmvec

At the pinned LÖVE commit, `b7daef0f7`. Written as the report we would file; LÖVE accepts none made with generative AI (AGENTS.md, "Reporting upstream"), so it stays here.

libvorbis 1.3.7's `configure.ac` (lines 187 to 190) sets `-O3 ... -ffast-math` on Linux. That defines `__FAST_MATH__`, under which glibc's `bits/math-vector.h` declares vector versions of `sin`, `cos`, and `acosf` on x86_64, and GCC then calls them from `_ve_envelope_init`, `vorbis_lsp_to_curve`, and `vorbis_lpc_to_lsp`. The result needs `libmvec.so.1`, which the manylinux policy does not allow. It affects `love-appimage-source`'s Makefile, which builds libvorbis this way.

Lota adds `-U__FAST_MATH__` to libvorbis's configure through a makefile read after LÖVE's (`tasks/linux_build.rb`).
