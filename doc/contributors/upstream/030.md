# `love.graphics.newCubeTexture` gives every face of a mipmap the same face

At the pinned LÖVE commit, `b7daef0f7`. Written as the report we would file; LÖVE accepts none made with generative AI (AGENTS.md, "Reporting upstream"), so it stays here.

A cube texture made from a list of images, each holding all six faces in one of the layouts `newCubeFaces` cuts, has the wrong faces: every face of mipmap `i` shows face `i` of image `i`, not its own face. With a seventh image, LÖVE reads past the end of the six faces.

## What happens

`w_newCubeTexture` (`src/modules/graphics/wrap_Graphics.cpp`) reads a table of images that is not a table of tables as one image per face, until an image is not square or one before it was not (lines 1047-1072). From then on each image is a mipmap of the whole cube: `Image::newCubeFaces` (`src/modules/image/Image.cpp`, lines 124-194) cuts it into six faces, ordered +x, -x, +y, -y, +z, -z. The loop that stores them (lines 1066-1067) is:

```cpp
for (int face = 0; face < (int) faces.size(); face++)
	slices.set(face, i, faces[i]);
```

It indexes `faces` by `i`, the image's place in the list, where it means `face`. So mipmap 0 gets the +x face on all six sides, mipmap 1 the -x face, and so on. A seventh image, a cube of seven mipmaps, reads `faces[6]`, past the end of the six, which is undefined behavior.

The other forms are right: one image of all six faces (lines 1000-1015) and a table of tables, one per face (lines 1021-1044), both set each face from its own data.

## To reproduce

We read this and did not run it. A cube from a list of two images, a 12-by-2 strip of six 2-by-2 faces of different colors and a 6-by-1 strip of the same colors, should have six different colors on its first mipmap; by the code above, all six are the color of the first face. Reading the faces back with `love.graphics.readbackTexture(cube, face)` for each face shows it.

## A fix

Index by the face: `slices.set(face, i, faces[face]);`.

## What Lota does

`Lota::Graphics::CubeTexture.new` ports the loop as LÖVE has it, so a game gets the faces LÖVE gives (`add_cube_list` in `ext/lota/native/texture.cpp`). Where LÖVE reads past the six faces, Lota reads them with `std::vector::at` and raises instead. Whether Lota should set each face from its own data, as LÖVE means to, rather than match what LÖVE does, is a question for the maintainer.
