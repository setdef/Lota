# love-android ends a running game when dark mode, the font, the language, the display size, or the wallpaper's colours change

In love-android's `main` branch at `1c89bb0b2e` (2026-11-03), which builds LÖVE 12 from a commit 15 commits past the one Lota pins, `b7daef0f7`, with SDL's Java classes of SDL 3. Written as the report we would file; LÖVE accepts none made with generative AI (AGENTS.md, "Reporting upstream"), so it stays here.

`GameActivity` declares the configuration changes it handles itself as `android:configChanges="orientation|screenSize|smallestScreenSize|screenLayout|keyboard|keyboardHidden|navigation"` (`app/src/main/AndroidManifest.xml`, line 36, unchanged since `dcd27223bf`, 2024-10-13). For any other change, Android destroys the activity and makes a new one. SDL's activity cannot carry a game across that. `SDLActivity.onDestroy` sends the game a quit and waits up to a second for SDL's thread, and the new activity's `onCreate` finds that one has already run, and calls `System.exit(0)` unless the hint `SDL_ANDROID_ALLOW_RECREATE_ACTIVITY` is set (SDL 3.4.10, `android-project/app/src/main/java/org/libsdl/app/SDLActivity.java`, `onCreate` and `onDestroy`).

The manifest does set that hint, but on the `<activity>` (line 40), and SDL reads `SDL_ENV.` meta-data only from the `<application>` (`SDLActivity.getManifestEnvironmentVariables`, which reads `getApplicationInfo(..., GET_META_DATA).metaData`). So the hint has no effect, and the app exits.

Changes that players make, or that Android makes for them, and that the list leaves out:

- dark mode, `uiMode`, which can also change on a schedule;
- the font's size, `fontScale`, and bold text, `fontWeightAdjustment`;
- the app's or the system's language, `locale`, which Android 13's per-app languages also change, and which changes `layoutDirection` along with it;
- the display size, `density`, which "Display size" in the settings changes (`adb shell wm density 560` does the same), and which SDL's manifest leaves out too;
- the system's resource overlays, `assetsPaths`. Android 12 and newer enable overlays when the wallpaper's colours change. The attribute's value is in the platform's `attrs.xml`, though Android's documentation of `configChanges` does not list it.

SDL's own manifest at `release-3.4.10` (`android-project/app/src/main/AndroidManifest.xml`, line 85) declares `layoutDirection|locale|grammaticalGender|fontScale|fontWeightAdjustment|orientation|uiMode|screenLayout|screenSize|smallestScreenSize|keyboard|keyboardHidden|navigation`. SDL added the language, gender, and font entries in `bf351b0b0e` (#11145), because a change of language restarted the app. `SDLActivity.onConfigurationChanged` passes changes of language and dark mode on to the game as `SDL_EVENT_LOCALE_CHANGED` and `SDL_EVENT_SYSTEM_THEME_CHANGED`, which LÖVE 12 delivers as `love.localechanged` and `love.themechanged` (`src/modules/event/sdl/Event.cpp`, lines 574-577). With love-android's manifest, those events cannot arrive while the game runs, because the change ends the game first.

## To reproduce

love-android's own debug APK from its CI run 41632391450 (`app-normal-record-debug.apk`, at `1c89bb0b2e`), on a Google APIs x86_64 emulator, started with no game (`adb root`, then `adb shell am start -n org.love2d.android/org.love2d.android.GameActivity`), and then `adb shell cmd uimode night yes`.

`adb shell wm density 560` (the emulator's 420 dpi made larger) does the same: on API 36 the log shows the exit above, and on API 33 the Vulkan present crashes, as with dark mode.

`cmd overlay enable com.android.theme.font.notoserifsource` does the same to love-android's app on API 33. `settings put system font_scale 1.3`, `settings put secure font_weight_adjustment 300`, and `cmd locale set-app-locales PACKAGE --locales fr-FR` (or `ar-EG`) were tried on an app built from Lota's host, whose manifest then declared just what love-android's declares, and each ended its game on API 33 and API 36, as dark mode and the overlay did. The changes the system sends with each are in its own log, such as the keyboard's `changedMask : 200` for dark mode and `80000000` for an overlay.

## A fix

Declare in `configChanges` what SDL's manifest declares, together with `assetsPaths` and `density`. Moving the meta-data to the `<application>` would not keep the game. With the hint, the new activity starts a new SDL main, so the game would start over from the beginning rather than exit. The crash on Vulkan, a present after the surface is gone, is a defect of its own, which any departure from the screen can reach: `017.md` traces it.

## What Lota does

Lota's Android host (`ext/lota/phone/host/android/src/main/AndroidManifest.xml`) declares love-android's seven changes and `uiMode`, `fontScale`, `fontWeightAdjustment`, `locale`, `layoutDirection`, `assetsPaths`, and `density`. Each of these, when left out, let an emulator end Lota's game: on API 33 and API 36, through the triggers above, each change ended the game with love-android's list, and left it running with Lota's. With `layoutDirection` left out, a change to French ended it too on API 33, so the language needs both. `grammaticalGender`, which SDL declares, is left out. Setting the system's gender on API 36 (`cmd grammatical_inflection set-system-grammatical-gender`) changed the keyboard's configuration (`changedMask : 8000`) and not the game's, which kept running even with love-android's list. An app's own gender changes when the app asks for one through `GrammaticalInflectionManager`, which Lota never does. `mcc`, `mnc`, `touchscreen`, and `colorMode` stay out as well. Neither manifest declares them, and they were not tried, since the emulator offers no plain command that changes them (a new SIM, a new touchscreen, or a wide-gamut display). Lota's guide describes the departure (`doc/guide/phones.md`, "The hosts"), and `.github/phones/android_emulator.sh` turns on dark mode and an overlay while the game runs, and changes the display size, and fails if SDL finishes a second activity.

A game that survives a change of density keeps the scale it launched with, as in LÖVE. `getScreenScale()` in `src/common/android.cpp` caches its value in a static, and SDL reads the density only in `surfaceChanged`, which a change of density does not trigger, so no resize reaches the game and Lota adds no event. `Window.safe_area` reads live.

This is a change to Lota's own host, which a game copies and may change. It is not a patch to LÖVE's engine, and Lota does not set the recreate hint.
