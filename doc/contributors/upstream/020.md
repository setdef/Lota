# love.physics.newFixture reads a destroyed Shape through a null pointer

At the pinned LÖVE commit, `b7daef0f7`. Written as the report we would file; LÖVE accepts none made with generative AI (AGENTS.md, "Reporting upstream"), so it stays here.

The deprecated `love.physics.newFixture(body, shape)` copies a Shape that belongs to no Body onto `body`. Given a Shape that was on a Body and has been destroyed, it reads through a null pointer, and the game crashes instead of getting an error.

## What happens

`w_newFixture` (`src/modules/physics/box2d/wrap_Physics.cpp`, lines 282 to 296) reads the Shape with `luax_checkshape`, which checks only its type, and calls `Physics::newAttachedShape` (`src/modules/physics/box2d/Physics.cpp`, lines 133 to 163). That refuses a Shape whose fixture is in the World (`prototype->isValid()`, line 135), and otherwise copies its Box2D shape: `*(b2CircleShape *) prototype->shape` and its kin, by the type the Shape recorded when it was made (lines 140 to 157).

`Shape::destroy` (`src/modules/physics/box2d/Shape.cpp`, lines 137 to 163) sets `fixture`, `shape`, and `body` to null, and leaves `shapeType` as it was. A destroyed Shape is therefore not "valid" (`isValid` tests `fixture`, `Shape.h`, line 63), passes the check, and its `getType()` still names a circle or a polygon, so `newAttachedShape` copy-constructs a Box2D shape from a null pointer. The Shape's own methods guard against this with `throwIfShapeNotValid`, "Cannot call this method on a destroyed Shape." (`Shape.cpp`, lines 171 to 175); `newAttachedShape` does not.

## To reproduce

```lua
local world = love.physics.newWorld()
local body = love.physics.newBody(world, 0, 0, "dynamic")
local shape = love.physics.newCircleShape(body, 10)
shape:destroy()
love.physics.newFixture(body, shape) -- crashes
```

## A fix

In `newAttachedShape`, refuse a Shape whose `shape` is null, as the Shape's own methods do, before reading it: `if (!prototype->isShapeValid()) throw love::Exception("Cannot call this method on a destroyed Shape.");`.

## What Lota does

Lota binds `newFixture` by hand (`ext/lota/native/physics.cpp`, `new_fixture`) and makes that check itself before it calls `newAttachedShape`, so `Lota::Physics::Fixture.new` raises RuntimeError with the Shape's own message. No patch to LÖVE is needed. `test/native/physics_fixture_test.rb` checks it.
