# Lövetest's `mountCommonPath` test passes only after other tests and in a home that has a Desktop

At the pinned LÖVE commit, `b7daef0f7`. Written as the report we would file; LÖVE accepts none made with generative AI (AGENTS.md, "Reporting upstream"), so it stays here.

`love.test.filesystem.mountCommonPath` (`testing/tests/filesystem.lua`, lines 400-419) asserts that mounting `appsavedir` fails, because "This is already mounted, we can't do it again." Whether it is mounted depends on what ran first. `setIdentity` mounts the save directory only when it already exists, and otherwise leaves it to be made and mounted the first time the game writes (`src/modules/filesystem/physfs/Filesystem.cpp`, lines 229-236 and 357-376). Lövetest runs a module's tests in the order of their names (`testing/classes/TestModule.lua`, lines 68-71), so `append`, `createDirectory`, and `getDirectoryItems` have written to the save directory before `mountCommonPath` runs, and the assertion holds. Run alone, or first, on a machine where the save directory does not exist yet, `mountCommonPath('appsavedir', 'appsavedir', 'readwrite')` makes the directory and mounts it at `appsavedir`, returns `true`, and the test fails. Worse, the save directory is then mounted at `appsavedir` rather than at the root, so the next write's `setupWriteDirectory` finds it mounted already (`mountFullPath`, line 428), fails, and every later test that writes fails too.

The same test asserts that `userdesktop` and `userdocuments` mount, which needs the folders `getFullCommonPath` names to exist: on macOS, the home's Desktop and Documents. They do in a person's home and on GitHub's runners, but not in a home made for a test run, where `PHYSFS_mountRW` refuses a folder that is not there.

To reproduce: delete the save directory for the identity `lovetest`, then run Lövetest with only `love.test.filesystem.mountCommonPath`.

A fix would have the test write a file first, as the tests before it happen to, and make the user folders it mounts, or skip them where they do not exist.

What Lota does: Minitest runs tests in random order, so Lota's translation (`test/lovetest/tests/filesystem.rb`, `test_mount_common_path`) writes and removes a file before it mounts, which leaves the save directory as the earlier tests leave it in Lövetest, and the home each test run gets has a Desktop and a Documents folder on macOS (`test/test_home.rb`, `TestHome.enter`), as a person's has. The assertions are LÖVE's, unchanged.
