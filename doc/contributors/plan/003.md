# Plan 003: Ship 1.0

Lota 1.0.0 is the first release whose API holds still: after it, renaming or removing a public method waits for 2.0. This plan lists what stands between trunk and that release. Take any item under "What's left", land it on trunk through the gate as AGENTS.md describes, and delete its line here in the same commit.

## What 1.0 means

- Every test in Lövetest, LÖVE's test suite (`vendor/love/testing/tests`), translated by the translation rules (`doc/contributors/design/translation.md`), passes from the installed gem on every platform Lota ships a gem for. A test skips only where Lövetest skips it.
- Every function in LÖVE's `wrap_*.cpp` files is bound in all its forms, or `ext/lota/bindings.rb` says why not.
- flash-blip, the heaviest of the published games Lota tests against, plays in Lota as it plays in LÖVE.
- A developer ships a game that draws: a signed and notarized Mac app, Windows and Linux apps, and iPhone, iPad, and Android builds from prebuilt libraries, with no clone of Lota.
- The README teaches the API a beginner meets first.

## What needs the maintainer

### Decisions

1. **Keep `lota fuse`, or have developers run Fledge themselves?** If Fledge, `lota run path/to/game` could become `lota path/to/game`, as LÖVE's `love path/to/game`. Changes the command line, `doc/contributors/design/packaging.md`, and the README's "Sharing a game".
2. **How is a phone game laid out and started, and does `lota fuse` build phone apps?** Changes `doc/guide/phones.md`, the hosts in `ext/lota/phone/host`, and the prebuilt libraries below.
3. **Keep the iOS host's two departures from LÖVE?** Its `Info.plist` hides the status bar, which LÖVE leaves to SDL, and it turns off the joystick SDL makes of the accelerometer, which LÖVE's iOS app keeps (`doc/guide/phones.md`, "iOS"). Changes every iPhone and iPad game.
4. **Patch or document stencil, depth, and MSAA at a fractional display scale?** LÖVE's Metal backend leaves the last pixel columns undrawn on a landscape iPhone mini (`doc/contributors/upstream/011.md`). A patch fixes games; a note keeps the engine unmodified.
5. **Should the README and each app's notices say where to buy a commercial license?** Changes what every shipped game carries.
6. **Should a Windows app's notices name winpthreads?** Its MIT notice is recorded for `OpenAL32.dll` but not for Lota's extension, which links it too.
7. **Should `lota fuse` build sandboxed Mac App Store apps?** Fledge would first need to take an entitlements file. Changes what Mac games can sell in the App Store.
8. **May an agent's finding about Mesa's llvmpipe shader bug go to Mesa?** Reporting publishes outside this repository.
9. **Can a `.love` archive hold Ruby?** Changes what `lota run` opens and how a game is handed to a player.
10. **Approve the new wording of ADR 007 and of "Threads and Ractors" in `doc/contributors/design/engine.md`** that the threads work brings.

### Credentials

- An Apple Developer ID and notarization profile, for a signed and notarized Mac app (`lota fuse --sign`, `--notarize`).
- An Apple team, for a real App Store (IPA) export.

### A person or a device

- Install the Mac `.dmg` and the Windows installer by hand, and play the game.
- On a real iPad with iOS 27, check the landscape fix in landscape and portrait, and whether a turn reaches the game as `Lota.displayrotated` (`doc/contributors/upstream/019.md`).
- Run Lota's unmodified iOS host on an iPhone.

## What's left

### Bindings and tests

- `readbackBuffer`, `readbackBufferAsync`, `copyBuffer`, `copyBufferToTexture`, `copyTextureToBuffer`, `drawFromShader`, `drawFromShaderIndirect`, and `SpriteBatch:attachAttribute`, which no Lövetest test calls.
- The missing forms of about 16 hand-bound functions: `play`, `stop`, and `pause` of several Sources; `points` with colours; `captureScreenshot` to a Channel; and some forms of `newByteData`, `newImageData`, `newRasterizer`, `filesystem.read`, `print`, `printf`, `setColor` from a table, and `newTextBatch`. Each says what it leaves out in `ext/lota/bindings.rb`.
- Lövetest's `captureScreenshot` test, which compares the window with the screen Lövetest's `love.draw` shows.
- `showFileDialog`, once tests can answer SDL's file dialog.
- `newCubeFaces` as `Lota::Image.new_cube_faces`, returning six ImageData (rule 17).
- `newFile` and `newFileData`'s forms that return the object, or `nil` and a message.
- `filesystem.load`'s binary mode (`:b`), loading Ruby's compiled instruction sequences as LÖVE loads Lua bytecode.
- Threads: rebase `experiment/threads-ractors-2`, translate Lövetest's five thread tests, and land them once the maintainer approves that wording.
- flash-blip, after threads: translate it and pass the parity harness.
- When LÖVE tags 12.0, move `vendor/love` to the tag, regenerate the source lists and bindings, rerun every test, and write the steps in `doc/contributors/development.md`.

### Platforms and shipping

- A fused app that draws, checked in the Fuse workflow on every platform. Today's fuse games open no window.
- Restart without `exec`, as LÖVE restarts in the same process. Phones forbid `exec`, and the App Sandbox kills it on macOS 15.
- iOS audio decoding through Core Audio (`LOVE_SUPPORT_COREAUDIO` and `CoreAudioDecoder.cpp`), as LÖVE's iOS build compiles it.
- Prebuilt engine and extension libraries for each iOS slice and Android ABI, built in CI and fetched by checksum.

### Tooling and docs

- After the in-progress bindings land, rewrite the README as a whole, reading both READMEs first: lead beginners to examples rather than the translation table, and warn that rule 4 makes `if Lota::Filesystem.write(f, s)` always true, so write `.first`.
- A RuboCop cop, generated from the binding table, that flags a rule-4 method used directly as a condition.
- Bring the binding generator's rule numbers and texts in line with the rewritten table in `doc/contributors/design/translation.md`.
- Fix `doc/guide/translating.md`, which says a type's name is a Symbol; rule 16 makes it a String.
- Stop `LotaRunTest`'s Lövetest totals from conflicting on every change and from failing when the laptop runs on battery.
- Tier the pre-push gate so a small change runs fewer checks.
- Beginner tutorials written for Lota, likely after 1.0.

## Decided

Earlier plans settled these, and no ADR, design document, guide, or RDoc says them yet. Each moves to an ADR of its own or to the documentation of its area.

- On iOS, Lota follows LÖVE's iOS build: Apple's OpenAL framework, so no LGPL code is linked, and Core Audio's decoder.
- Prebuilt engine libraries for each target are the default, fetched by checksum, and building from source stays supported. A newcomer ships without a terminal; a studio gets a project it can open, sign, and rebuild.
- Lota adds no renderer fallback. A game that may meet an unusable Vulkan leaves it out with `t.graphics.excluderenderers`, as in LÖVE.
- `lota fuse` keeps a short command line. A flag is added only when a game needs it; the signing flags pass Fledge's options through.
- Deprecation notices start `Lota - Warning:` and keep LÖVE's parameter names word for word.
- A record takes the name of the getter that returns it (`FullscreenMode`). `Shader#send` keeps LÖVE's name, and Lota's tests call it through `__send__`.
- A Mesh's `attach_attribute` and `detach_attribute` have no block form until a game needs one. A ParticleSystem's `start` and `stop` are not a pair, because they run across frames.
- Threads are Ractors. The extension calls `rb_ext_ractor_safe(true)` before it defines methods; an engine object crosses Ractors only when its type is frozen and shareable; each Ractor keeps a separate wrapper map; and Lota turns off the experimental warning with `Warning[:experimental] = false`.
- A published game qualifies as a parity test only when its code and every asset are under licenses compatible with AGPL-3.0-or-later. A game written for an older LÖVE gets only the renames `vendor/love/changes.txt` lists, as a patch beside it. Lövetest is translated from the copy in `vendor/love`, never from its standalone repository, which declares no license.
