# Plan 003: Ship 1.0

Lota 1.0.0 is the first release whose API holds still: after it, renaming or removing a public method waits for 2.0. This plan lists what stands between trunk and that release. Take any item under "What's left", land it on trunk as AGENTS.md describes, and delete its line here in the same commit.

## What 1.0 means

- Every test in Lövetest, LÖVE's test suite (`vendor/love/testing/tests`), translated by the translation rules (`doc/contributors/design/translation.md`), passes from the installed gem on every platform Lota ships a gem for. A test skips only where Lövetest skips it.
- Every function in LÖVE's `wrap_*.cpp` files is bound in all its forms, or `ext/lota/bindings.rb` says why not.
- flash-blip, the heaviest of the published games Lota tests against, plays in Lota as it plays in LÖVE.
- A developer ships a game that draws: Mac, Windows, and Linux apps, of which `lota fuse` signs the Mac and Windows ones with the developer's own identity and hands the Mac one to Apple's notary with the developer's own account, and iPhone, iPad, and Android builds from prebuilt libraries, with no clone of Lota.

## What needs the maintainer

### Decisions

1. **Keep `lota fuse`, or have developers run Fledge themselves?** If Fledge, `lota run path/to/game` could become `lota path/to/game`, as LÖVE's `love path/to/game`. Changes the command line, `doc/contributors/design/packaging.md`, and the README's "Sharing a game".
2. **Keep the iOS host's two departures from LÖVE?** Its `Info.plist` hides the status bar, which LÖVE leaves to SDL, and it turns off the joystick SDL makes of the accelerometer, which LÖVE's iOS app keeps (`doc/guide/phones.md`, "The hosts"). Changes every iPhone and iPad game.
3. **Patch or document stencil, depth, and MSAA at a fractional display scale?** LÖVE's Metal backend leaves the last pixel columns undrawn on a landscape iPhone mini (`doc/contributors/upstream/011.md`). A patch fixes games; a note keeps the engine unmodified.
4. **Should the README and each app's notices say where to buy a commercial license?** Changes what every shipped game carries.
5. **Should a Windows app's notices name winpthreads?** Its MIT notice is recorded for `OpenAL32.dll` but not for Lota's extension, which links it too.
6. **Should `lota fuse` build sandboxed Mac App Store apps?** Fledge would first need to take an entitlements file. Changes what Mac games can sell in the App Store.
7. **May an agent's finding about Mesa's llvmpipe shader bug go to Mesa?** Reporting publishes outside this repository.

## What's left

### Platforms and shipping

- A player app that plays a `.lota` by unpacking it, and `lota run game.lota` (`doc/contributors/design/packaging.md`, "A game in one file").
- Attach the fuser app to each release: `.github/workflows/fuse.yml` keeps each platform's fuser as the artifact `fuser-PLATFORM`. On Windows, see a `.lota` opened with the fuser, or dropped on its window, become an app, which the build machines could not show yet (`doc/contributors/design/packaging.md`, "A game in one file").
- See a sandboxed app restart in its process on macOS 15. A game restarts in its process by default on every platform, as LÖVE's does, and the Fuse workflow's macOS job restarts `test/games/fuse_sandbox` under the App Sandbox (`.github/sandbox_run.sh`); delete this line once that step has passed on CI's `macos-15` runner, or fix what it shows (`doc/contributors/design/game.md`, "Restarting").
- Publish the prebuilt phone engines with each release. CI's release job now attaches the four bundles from `.github/workflows/phone-engine.yml` and Lota's source gem, `lota-VERSION.gem`, which pins that release's engines, and the changelog job then pins them on trunk in `ext/lota/phone/engines.txt`; what is left is the first release that does so, and the changelog job's commit that pins it on trunk.
- Prebuilt extension libraries for each iOS slice and Android ABI, once Lota requires Ruby 4.1, whose ABI they are built against, packed and fetched as the engines are.
- Show that `lota fuse` signs. CI signs a fused Mac app and a fused Windows app, each with an identity it makes for the run, and checks each signature; and it hands a Mac app to a stand-in for Apple's notary tool, to show what reaches it. No check needs an account of the maintainer's. Whether Apple accepts an app with the JIT's entitlements stays unknown, as ADR 010 records it, until a developer with an account notarizes a game.

### Tooling and docs

- For the release candidate: the performance guide (`doc/guide/performance.md`) has Linux's numbers only; it needs macOS's, Windows', and the phones', each from `rake bench` in a quiet run. On an idle Mac with Xcode and a desktop session, run `BENCH_SCENARIOS=flash_blip,flash_blip_native_calls bundle exec rake bench`, which no Mac has run whole yet. On Windows `rake bench` does not run yet: Windows has no reference love, and `Bench.spawn`'s process groups, `Bench::Machine`, and the harness libraries the game scenario preloads are Unix's only, and it must skip the JITs RubyInstaller's Ruby lacks. On a phone it has no way to build, install, run, and read back its game.
- Beginner tutorials written for Lota, likely after 1.0.

## Decided

Earlier plans settled these, and no ADR, design document, guide, or RDoc says them yet. Each moves to an ADR of its own or to the documentation of its area.

- Prebuilt engine libraries for each target are the default, fetched by checksum, and building from source stays supported. A newcomer ships without a terminal; a studio gets a project it can open, sign, and rebuild.
- Lota adds no renderer fallback. A game that may meet an unusable Vulkan leaves it out with `t.graphics.excluderenderers`, as in LÖVE.
- `lota fuse` keeps a short command line. A flag is added only when a game needs it; the signing flags pass Fledge's options through.
- Deprecation notices start `Lota - Warning:` and keep LÖVE's parameter names word for word.
- A record takes the name of the getter that returns it (`FullscreenMode`). `Shader#send` keeps LÖVE's name, and Lota's tests call it through `__send__`.
- A Mesh's `attach_attribute` and `detach_attribute` have no block form until a game needs one. A ParticleSystem's `start` and `stop` are not a pair, because they run across frames.
- A published game qualifies as a parity test only when its code and every asset are under licenses compatible with AGPL-3.0-or-later. A game written for an older LÖVE gets only the renames `vendor/love/changes.txt` lists, as a patch beside it. Lövetest is translated from the copy in `vendor/love`, never from its standalone repository, which declares no license.
