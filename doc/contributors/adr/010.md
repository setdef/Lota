# ADR 010: Ship Games Through Fledge's Embedded Ruby

## Context and Problem Statement

A player of a fused LÖVE game double-clicks an app and it runs, with nothing to install. A Lota game needs a Ruby interpreter, the standard library, its gems, Lota's native extension, and LÖVE's engine, and almost no player has Ruby. How does a Lota game reach a player looking exactly like a fused LÖVE game?

## Decision Drivers

- The player installs nothing and sees an ordinary app.
- Ruby runs on the process's main thread, as the engine needs, with YJIT.
- The app controls its own layout and code signing on macOS.
- Nothing on the player's machine changes how the game runs.
- Upkeep of runtimes and launchers that one maintainer can carry.

## Considered Options

1. Fledge, the maintainer's packaging tool for Ruby apps, which embeds CRuby in a launcher and publishes a runtime for each platform.
2. A launcher and runtimes of Lota's own, built the same way.
3. A single-file packager such as Tebako or OCRAN.

## Decision Outcome

Chosen: option 1, so that Lota does not duplicate what Fledge already does.

Lota first chose option 2, on 2026-10-25, and a spike outside Lota's repository showed its core works: a small C launcher that embeds CRuby, runs game code on the main thread with YJIT, and passes strict code-signature checks. Fledge is that design, generalized and written afresh as a tool shared by several of the maintainer's projects. On 2026-11-02, once two Lota games built with Fledge ran on macOS with no Ruby on the player's path, option 2 was dropped in its favour.

Option 3 lost on 2026-10-25: Tebako and OCRAN were built for command-line tools. They unpack to a temporary directory or mount a virtual filesystem on every launch, and they control less of a macOS app's layout and signing.

Confidence: high that fused games run with nothing installed on every desktop platform, as CI checks on every push and as a person found installing and playing one on macOS and on Windows; unknown whether Apple accepts the JIT's entitlements under a Developer ID signature, since no app has had one yet.

### Consequences

- Good, because Lota writes a Fledge project and builds it with `lota fuse`, rather than maintaining a launcher and runtimes.
- Good, because Lota's gem needs nothing special: Fledge copies a game and the gems its lockfile names into its runtime.
- Good, because the same maintainer sets both projects' priorities, so a fix Lota needs can land in Fledge first.
- Bad, because Lota's packaging depends on a second project's releases: `lota fuse` pins a Fledge version, and each new release is a pin to move and test.
- Bad, because Lota publishes a precompiled gem per platform, matched to Fledge's Ruby, and a new Fledge Ruby needs a matching Lota gem first.
- Bad, because Fledge builds an app only on its own platform, so a developer builds on each platform they ship for, and CI fuses on five runners.
- Bad, because a fused game carries Ruby and is larger than a fused LÖVE game.

### Confirmation

CI fuses games on every platform on every push and runs each app with no Ruby on its path, and a release waits for it.

## More Information

What `lota fuse` writes, what it needs, the platforms, signing, and notices: [design/packaging.md](../design/packaging.md). Whether developers run Fledge themselves in place of `lota fuse` is the maintainer's open question; its answer would amend this decision.
