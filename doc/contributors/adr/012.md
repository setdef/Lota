# ADR 012: Restart a Game by `exec`

## Status

Accepted

## Date

2026-11-07

## Context and Problem

`love.event.restart` ends a LÖVE game and starts it again. `love.run` returns `"restart"`, and `love.cpp`'s `main` closes the Lua state and runs the game again in the same program, with the same arguments, passing the value on as `love.restart` (`src/love.cpp`, `runlove` and `main`). A fused game is fused again because the program is. Ruby cannot close the world a game defined. How does a Lota game restart, both under `lota run` and fused?

## Decision Drivers

- Restart in every case LÖVE does, fused games included.
- A fresh start: no classes, engine modules, audio devices, or threads left over.
- One way that works on macOS, Linux, and Windows.

## Considered Options

1. Replace the process with `exec`, running the program the process runs again, with the same arguments.
2. Restart in the same process, inside a `Ruby::Box` dropped on restart.
3. `exec RbConfig.ruby, $0, *ARGV`.

## Decision Outcome

Chosen: option 1. Under `lota run` the program is Lota; in a fused game it is Fledge's launcher, which sets the app up as it first did. A spike of option 2 on Ruby 4.0.7 failed: Ruby never frees a box that defines a named module, and every Lota box defines `Lota`, so five restarts left five engine copies with their audio devices and threads, about 36 MB each. The box also loaded its own copy of the extension from a temporary directory, broke `$stdout` redirection, and could not keep the window. Option 3 runs the console Ruby on Windows rather than the app. Revisit option 2 when a Ruby release frees boxes.

### Consequences

- Good, because a restart is a fresh start, and Lota needs no way to release its engine modules, as LÖVE's `lua_close` does.
- Bad, because Windows has no `exec`: Ruby starts a new process and waits, so the old process stays, with any audio device it opened, until the new run ends.
- Bad, because phones forbid replacing a process, so a phone game cannot restart.
- Bad, because the macOS App Sandbox kills the new image on macOS 15.
