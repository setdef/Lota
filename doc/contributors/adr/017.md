# ADR 017: Make an App from a `.lota` by Dropping It on a Fuser App

## Context and Problem Statement

A LÖVE developer turns a game into an app of its own by hand: they append the `.love` to LÖVE's executable on Windows, or put it in a copy of LÖVE's macOS app and edit its `Info.plist` ([LÖVE's wiki, Game Distribution](https://love2d.org/wiki/Game_Distribution)). LÖVE ships no tool for it. Lota's `lota fuse` builds an app in one command, but only for a developer who has installed Ruby and uses a terminal.

On macOS, a hand edit breaks a Lota app where it does not break LÖVE's. Fledge, which builds Lota's apps ([ADR 010](010.md)), seals every Mac app it signs without a developer's identity ([Fledge's ADR 050](https://github.com/setdef/Fledge/blob/trunk/doc/contributors/adr/050.md)). A downloaded app whose seal an edit broke is refused as "damaged", with no way past, where LÖVE's app, which carries no seal, gets only the ordinary refusal for an unsigned app. How does a newcomer, with a `.lota` ([ADR 016](016.md)) and no terminal, make an app a player can run?

## Decision Drivers

- A newcomer makes an app without a terminal, Ruby, or Xcode.
- The player app stays LÖVE's app, and adds nothing of its own ([ADR 016](016.md)).
- A downloaded app meets no worse than the ordinary refusal for an unsigned app.

## Considered Options

1. A separate fuser app, onto which a `.lota` is dropped to make an app.
2. The player app also makes an app, from a menu.
3. Fusing by hand only, as in LÖVE: the player app finds a game added to it.
4. `lota fuse` only.

All four were weighed on 2026-11-13.

## Decision Outcome

Chosen: option 1, because it alone gives a newcomer an app from a drop while the player app stays LÖVE's, and its apps are sealed as Fledge builds them. The maintainer decided on 2026-11-13.

Lota ships a fuser app on each desktop, built with Fledge. A `.lota` dropped on it becomes an app of its own through Fledge's `fledge build --from`, which copies a built app, puts the game in it as real files, gives the copy its own name and identity, and seals it again on macOS. The fuser is its own template: it carries Lota, the gems a game may use, and Fledge. LÖVE has no counterpart, so the fuser adds to LÖVE rather than departing from it.

Option 2 lost because it adds to the player app what LÖVE's lacks, and a drop on it would mean either of two things; with an app of its own, each app's drop means one thing. Option 3 lost because on macOS a newcomer's hand-fused app reads as damaged unless they seal it again in a terminal. LÖVE avoids that only because its universal program's Intel half is unsigned, a state an Apple silicon program cannot copy and still run, so Fledge keeps its seal; the player app therefore looks for no game added to it. Option 4 lost because it needs Ruby and a terminal; it remains for developers.

Confidence: high that `fledge build --from` makes a sealed app, low for the rest. Fledge's own tests build an app with it on macOS, Windows, and Linux and verify its seal on macOS. No fuser exists yet. That a fused app, downloaded, gets the ordinary refusal rather than "damaged" is inferred from the measurement of an intact sealed app, below, not measured.

### Consequences

- Good, because a newcomer makes an app from a zipped folder with one drop, where LÖVE's developers fuse by hand or with others' tools.
- Good, because the apps it makes are sealed, so macOS treats them as it treats any unsigned app, and their game is real files.
- Bad, because Lota builds, tests, and ships a fuser for each desktop with every release.
- Bad, because an app it makes is as large as the fuser, Fledge included, holds only the gems the fuser ships, and runs only on the system it was made on.
- Bad, because a developer cannot follow LÖVE's manual fusing steps, and uses the fuser, `lota fuse`, or `fledge build --from` instead.

### Confirmation

Tests drop a `.lota` on the fuser on each desktop, run the app it makes, and check on macOS that the app's seal verifies.

## More Information

Measured on the maintainer's Mac, macOS 27, each app downloaded and opened:

| App | macOS's dialog |
|---|---|
| LÖVE 12's `love.app`, as shipped or with a `.love` added | "Not Opened", which Open Anyway clears |
| A sealed app, as built | "Not Opened", which Open Anyway clears |
| A sealed app, edited and not sealed again | "is damaged and can't be opened", with no way past |
| An unsealed Fledge app, even unedited | "is damaged and can't be opened", with no way past |
