# ADR 004: Run LÖVE's Own C++ Engine and Replace Only Its Lua

## Status

Accepted

## Date

2026-10-24

## Context and Problem

Lota lets Rubyists make 2D games the way LÖVE lets Lua programmers make them. LÖVE is a C++ engine that hands control to Lua: `boot.lua` starts the game, `callbacks.lua` runs its loop, and 156 `wrap_*.cpp` files expose the engine to Lua. A decade of tutorials teaches games in that API.

A game written in Lota has to behave as the same game written in LÖVE: the same physics, rendering, audio, and event order. In a game, behavior is the product. A platformer ported line for line must jump, slide, and collide the same way, or the tutorials stop being true. Where does that behavior come from?

## Decision Drivers

- Same behavior as LÖVE, down to physics contacts and event order.
- Parity that a test can check, not just claim.
- LÖVE's tutorials stay true for Lota.

## Considered Options

1. Bind LÖVE's own C++ engine, and replace only the Lua around it.
2. Build an engine of Lota's own from other libraries.

No other option was recorded.

## Decision Outcome

Chosen: option 1. LÖVE's renderer, audio, physics, shader dialect, and batching are the behavior, and only LÖVE's own engine has them. Lota compiles the engine at a pinned commit without its Lua layer, ports `boot.lua` and `callbacks.lua` to Ruby line by line, and binds the rest.

### Consequences

- Good, because parity is testable. Both engines run the same C++, so the same game in Lua and in Ruby can run side by side on the pinned commit and be compared frame by frame and contact by contact.
- Good, because LÖVE's documentation, wiki, and tutorials describe Lota's behavior too.
- Bad, because building Lota means building LÖVE. A contributor needs LÖVE's dependencies, and a clone compiles a large C++ codebase. Players and game developers install precompiled gems instead.
- Bad, because upgrading LÖVE is work: bump the submodule, regenerate the source lists, update the patches, and rerun the parity tests.
- Bad, because LÖVE's design decisions, and its defects, become Lota's. Lota works around a defect in its own code, or patches as a last resort (ADR 005).
