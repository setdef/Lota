# ADR 002: Ship a Lota Game as LÖVE Ships a Fused Game

## Status
Accepted, except for the Windows toolchain (section 4), which waits on a spike.

## Date
2026-10-25

## Context

A player who downloads a game made with LÖVE never meets LÖVE or Lua. The developer "fuses" the game: they join the zipped game onto LÖVE's executable (a renamed `.exe` beside its DLLs on Windows, a renamed `.app` with the game inside on macOS, an AppImage on Linux), and at boot LÖVE notices that its own executable carries a game and runs it (`vendor/love/src/modules/love/boot.lua`, lines 76–96). The player double-clicks an app, and it runs.

A Lota game needs more than a LÖVE game does: a Ruby interpreter, Ruby's standard library, the game's gems, Lota's native extension, and LÖVE's engine with its libraries. Almost no player has Ruby installed. A player of a Lota game must still see exactly what a player of a fused LÖVE game sees.

A spike (`rove_2d-spikes/spike5`, outside the repository) proved the core of it on macOS: a 35-line C launcher that statically links a prebuilt Ruby 4.0.9, finds its standard library inside its own app bundle, runs game code on the main thread with YJIT on, loads Lota's extension unchanged, and passes strict code-signature verification.

## Decision

### 1. A launcher embeds Ruby, as LÖVE's executable embeds Lua

Lota ships a small launcher executable that embeds CRuby, following Ruby's own `main.c` (`setlocale`, `ruby_sysinit`, `ruby_start_main`). It points the interpreter at the Ruby inside the app, clears the player's own Ruby environment (`RUBYLIB`, `RUBYOPT`, `GEM_HOME`, `GEM_PATH`, `BUNDLE_GEMFILE`) so nothing on the player's machine changes the game, and runs the game on the process's main thread, as ADR 001 section 6 requires.

Single-file packagers such as Tebako and OCRAN were built for command-line tools: they unpack to a temporary directory or mount a virtual filesystem on every launch, and they control less of a macOS app's layout and signing than a launcher does.

### 2. Lota's CI prebuilds a runtime for each platform

For each platform, Lota's CI builds a runtime: the launcher, Ruby with its whole standard library and default gems, Lota's extension, and LÖVE's engine libraries. Fusing a game copies the game into a runtime, as fusing a LÖVE game does. A game developer can fuse for every platform from one machine, as long as the game's gems are pure Ruby or precompiled for each platform.

The standard library ships whole, as LÖVE ships the whole of Lua's, because a game that requires a library and finds it missing is broken. Bundled gems are gems like any other: a runtime carries one only when the game's Gemfile asks for it.

### 3. Ruby comes from rv-ruby on macOS and Linux

rv-ruby (spinel-coop/rv-ruby) publishes prebuilt, relocatable Ruby 4.0 builds for macOS and Linux, with a static libruby, YJIT, and ZJIT, linked against static copies of OpenSSL, libyaml, libffi, and zlib. Its Apple Silicon build needs macOS 14 or newer, and Lota supports macOS 15 and newer, so it fits.

### 4. Windows waits on a spike

The only maintained Ruby 4.0 for Windows is RubyInstaller, built with MinGW, while LÖVE's own Windows builds use Microsoft's compiler. Lota must either build LÖVE's engine with MinGW, which LÖVE's own builds do not do, or build and maintain a Ruby with Microsoft's compiler. A spike builds LÖVE with MinGW and runs Lövetest against it and against LÖVE's own Microsoft-compiler build of the same commit; this section is decided by its result.

### 5. Developers run `lota run` and `lota fuse`

During development, `lota run` runs a game on the developer's own Ruby, as `love path/to/game` does, following `rooibos run`. For release, `lota fuse` writes the game into the prebuilt runtime for each platform asked for, along with the notices Ruby's license and its libraries' licenses require.

## Consequences

- Lota's CI builds and publishes a runtime for every supported platform, so precompiled builds are part of the product, not an optimization.
- A fused game carries a Ruby interpreter, the standard library, and LÖVE's engine, so it is larger than a fused LÖVE game: about 58 MB on macOS before compression in the spike.
- The macOS runtime is code-signed with the hardened runtime. Ruby's JITs mark memory executable with plain `mprotect` rather than `MAP_JIT`, so the runtime carries `com.apple.security.cs.allow-unsigned-executable-memory`, an entitlement LÖVE's own macOS build already declares (`vendor/love/platform/xcode/love.entitlements`). Whether notarization accepts it under a Developer ID signature is confirmed when Lota first signs one.
- A fused game ships Lota itself, and with it Lota's license.
