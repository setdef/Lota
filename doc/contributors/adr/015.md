# ADR 015: Build Phone Apps from the Project Fledge Writes

## Context and Problem Statement

A phone runs no `lota run`, and no app store takes an app it did not see its developer sign. An iPhone or iPad app is built and signed in Xcode with the developer's Apple account, and an Android app in Gradle with the developer's own key. Lota ships games through Fledge ([ADR 010](010.md)), whose `fledge build ios` and `fledge build android` write such a project for an app, with Ruby, the app's gems, and their compiled extensions in it, and leave building, signing, and submitting it to the developer. LÖVE ships a fixed Xcode project and a fixed Android project, which the developer copies, puts `game.love` in, and builds by hand. How does a Lota game become a phone app?

## Decision Drivers

- A phone game is built and behaves as a LÖVE game's does.
- The developer signs with their own Apple and Google accounts; Lota holds no key of theirs.
- The project stays true to the game, its gems, and Lota's engine on every build.
- Upkeep that one maintainer can carry, and proof that needs no account but the developer's.

## Considered Options

1. The project Fledge writes, with Lota's startup files as Fledge's host files, which the developer builds and signs in Xcode or Android Studio.
2. A fixed phone project of Lota's own, as LÖVE ships, which the developer copies and puts the game in.
3. One command that builds and signs the finished phone app, so the developer never opens Xcode or Android Studio.

All three were weighed on 2026-11-13.

## Decision Outcome

Chosen: option 1. The maintainer decided on 2026-11-13, once it was known that LÖVE builds no phone app in one command either.

Option 3 lost for four reasons. LÖVE has no such command, so its developers expect to open Xcode or Android Studio for a phone game. The command saves less than it seems: the developer still needs Xcode, an Apple developer account and team, and an Android signing key, and skips only pressing Build. Proving that it signs needs the maintainer's own Apple and Google accounts, which would hold up Lota's release candidate. And it adds to Lota without changing anything already there, so it can come in any release. If it comes, it belongs in Fledge, for every framework that builds on Fledge, beside Fledge's desktop builds, which already sign with the developer's own identity in one command.

Option 2 lost because Fledge already writes the project. A fixed project of Lota's own would be a second one for the maintainer to keep, and would drift from the Ruby, gems, and extensions Fledge puts in the project on every build. A studio gets option 2's control without the drift: its own host files replace Lota's and Fledge's, as [Fledge's ADR 025](https://github.com/setdef/Fledge/blob/trunk/doc/contributors/adr/025.md) provides.

Confidence: high that the project builds and the game runs, low that it signs and passes a store. On every push, CI builds the project for iOS and Android and runs a sample game in iPhone and iPad Simulators and Android emulators, and games built this way have run on two iPhones, an iPad, and an Android phone. Signing and submission are unproven: no Lota game has yet been signed by a developer's team and sent to the App Store or Google Play.

### Consequences

- Good, because a phone game is built as a LÖVE game's is, in the developer's own tools, and Lota holds no key of the developer's.
- Good, because Lota keeps no phone project of its own: Fledge writes it, with Lota's hosts in `ext/lota/phone/host` as its host files.
- Good, because a one-command phone build, if it comes, comes from Fledge to every framework, and Lota needs no change of its own to use it.
- Bad, because a developer installs Xcode or the Android SDK and builds and signs in it, as in LÖVE, so shipping to a phone takes more than `lota fuse` takes on a desktop.
- Bad, because a beginner who has never used a terminal cannot reach a phone without one: the project comes from `fledge build` or the iOS kit's workflow, and then has to be built in Xcode or Android Studio, a professional tool with signing, certificates, and accounts to set up, before it runs on a phone. LÖVE asks as much of its developers, but a newcomer meets it at the moment they most want to share their game.
- Bad, because Lota's phone builds depend on Fledge's project generator and its releases, beside its desktop builds.

### Confirmation

- CI's `phones` job takes the steps of `doc/guide/phones.md` on a sample game on every push, for iOS and Android, and the `ios-kit` jobs build the project as a game's own CI would.
- `doc/guide/phones.md`, "What has run", records each device a build has run on.
