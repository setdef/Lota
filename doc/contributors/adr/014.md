# ADR 014: Release 1.0 on a Pinned LÖVE 12.0 Commit, Without Waiting for LÖVE 12.0

## Context and Problem Statement

Lota translates LÖVE 12.0's API, which is not yet released: `vendor/love` pins a commit of LÖVE's `main` branch, where 12.0 is developed. From 1.0.0 on, SemVer lets Lota rename or remove part of its public API only in a new major version. Does 1.0.0 wait for LÖVE to tag 12.0?

## Decision Drivers

- Lota follows SemVer from 1.0.0 on.
- Lota's behavior matches LÖVE's source at the pinned commit (AGENTS.md, "Design precedence").
- Lota's release does not depend on a schedule outside its maintainer's control.

## Considered Options

1. Release 1.0.0 on the pinned commit, and follow LÖVE 12.0 in later releases.
2. Wait for LÖVE to tag 12.0, move `vendor/love` to the tag, and release 1.0.0 on it.

## Decision Outcome

Chosen: option 1. The maintainer decided on 2026-11-12, after research that day showed LÖVE 12.0 has no release date. Its changelog section was started in 2020 and its GitHub milestone in 2021, and 11.5, on 2023-12-03, is LÖVE's latest release. A LÖVE developer's public expectation of a 12.0 release in 2025 passed unmet. Waiting would tie Lota's 1.0 to that open-ended schedule.

Confidence: high. Fidelity to LÖVE comes before any API Lota has released, so whatever LÖVE changes before it tags 12.0, Lota follows: an addition in a minor release, a rename or removal in a major one. The research found LÖVE's 12.0 milestone at 74 issues closed and 6 open, all small, and the API changes on LÖVE's `main` in the six months before the decision were additive.

### Consequences

- Good, because 1.0.0 waits only on Lota's own work and on Ruby 4.1.0 ([ADR 013](013.md)).
- Good, because LÖVE's changes since the pinned commit, and the 12.0 tag when it comes, reach Lota in later releases: additions in minor ones, renames and removals in major ones.
- Bad, because a LÖVE change that renames or removes something Lota has released costs Lota's users a major version to follow.
- Bad, because until LÖVE tags 12.0, Lota's fidelity is to a development commit, which its docs name, rather than to a release.

### Confirmation

- `vendor/love` stays pinned to a named commit, and moving the pin is a reviewed change that reruns Lövetest and the parity harness.
- Each move of the pin runs the release flow's API check, which marks a rename or removal as breaking, so it ships in a major release.
