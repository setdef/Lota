# ADR 006: Bind the Engine with Rice, and Revisit Ruby's C API When a Game's Binding Cost Calls for It

## Context and Problem Statement

Ruby has to call LÖVE's C++ classes and receive their objects. LÖVE's `wrap_*.cpp` files record each function's arity, overloads, defaults, and error messages for Lua, and each binding reproduces them. LÖVE has about 1,100 functions and methods, so a generator writes most bindings. How does Lota bind C++ to Ruby?

## Decision Drivers

- No third language between Ruby and LÖVE.
- Bindings a generator writes from the `wrap_*.cpp` files.
- Engine objects that Ractors can share where LÖVE allows it.
- A call cheap enough for a game's frame, on every platform Lota ships, phones included.

## Considered Options

1. Rice, which binds C++ classes to Ruby.
2. Ruby's C API, written directly, which the generator could emit.
3. Thin Rice bindings of the engine's methods, with the wrap logic in Ruby.
4. Rust, through Magnus and cxx.
5. Ruby's FFI, through the ffi gem or Fiddle, over a C layer of Lota's own.
6. SWIG, which generates wrappers from C++ headers and interface files.

Options 1 to 4 were weighed between 2026-10-24 and 2026-10-28, options 2 and 3 with measurements. Options 5 and 6 were researched on 2026-11-09, after the decision.

## Decision Outcome

Chosen: option 1, because it binds C++ classes with no third language between Ruby and LÖVE, and because the games measured did not need the speed of option 2.

Option 4 lost because going from Ruby through Magnus and cxx to C++ adds two layers and a second build system.

Option 2 lost because its speed did not matter yet, not on its merits. A call through Rice costs about ten times what LÖVE's does, yet the heaviest game Lota tests against holds 60 Hz on a near-worst-case iPhone and a mid-range Android phone. The one cost of option 2 on record is that Lota would take on what Rice does, the hardest part being C++ exceptions turned into Ruby exceptions. Patching Rice's slow path was offered at the same time, and no reason for passing it over was recorded. A faster binding changes no public API, so Lota weighs both again when game developers ask for more speed.

Option 3 lost against the maintainer's condition for it, that it remove most of the C++ and cost almost nothing per call. It would remove about half, would cost nothing per call only if every binding were written with care, and would make Rice's enum values unshareable between Ractors.

Options 5 and 6 were never weighed against Rice. The later research found that FFI would need a C function for each of LÖVE's C++ methods, a second layer beside the FFI declarations, though one build would then serve every Ruby version; and that SWIG's interface files are a third language, while LÖVE's arities, defaults, and error messages live in the `wrap_*.cpp` files, not in the headers SWIG reads.

Confidence: high that Rice is fast enough for today's games, by `rake bench` on desktops and phones and by the heaviest game's frame times. A heavier game, or a slower phone, would drop frames sooner in Lota than in LÖVE. Rice is not known to be better than options 2, 5, or 6.

### Consequences

- Good, because bindings are plain C++ that a generator writes from LÖVE's own wrap files, and each hand-written binding records why.
- Good, because Rice turns LÖVE's C++ exceptions into Ruby exceptions in one place.
- Bad, because a call costs about ten times what LÖVE's does, mostly Rice rebuilding its argument map on every call, and a phone multiplies that.
- Bad, because Lota depends on Rice's releases and reads its source for what it does, and writes the RBS for its bindings itself.
- Bad, because the extension compiles against Ruby's headers, so each gem names the Ruby versions it was built for, and a new Ruby needs a new build on each platform.
- Bad, because a move to Ruby's C API, if it comes, means a second code path in the generator for the maintainer to keep.

### Confirmation

The gate fails when the committed bindings differ from what the generator writes, and `rake bench` measures a call's cost against LÖVE's.
